# Развёртывание на сервере

Полный путь от пустого VPS до работающего праздника: гости открывают сайт с телефонов, телевизор показывает `/tv`, ведущий управляет из `/admin`.

## Как это устроено

```
телефоны, ТВ, ведущий ──HTTPS──▶ Caddy (порты 80/443) ──▶ app (порт 8080 внутри docker)
                                 сам получает сертификат        бэкенд .NET + собранный фронт
                                                                 SQLite и фото → том shrek-data
```

- **app** — один контейнер: API, SignalR (живые обновления) и фронт.
- **caddy** — принимает HTTPS, сам получает и продлевает сертификат Let's Encrypt, проксирует WebSocket.
- **Данные** — база `shrek.db`, загруженные фото и видео (`media/`), ключи входа (`keys/`). Лежат в docker-томе `shrek-data` и переживают пересборку.

## Что понадобится

| Что | Зачем | Пример |
|---|---|---|
| VPS с Ubuntu 22.04 или 24.04 | на нём всё крутится | 2 vCPU, 2 ГБ RAM, 20 ГБ диска — с запасом для ~15 гостей |
| Домен или поддомен | для HTTPS (без него не работают камера и полный экран на телефонах) | `shrek.example.ru` |
| SSH-доступ к серверу | установка | логин и ключ/пароль от хостера |
| На своём компьютере: git, ssh | залить код | в Windows уже есть (Git Bash) |

Сервер лучше брать в той же стране, где праздник, чтобы задержка была маленькой: в реакции и тапалке это заметно.

## 1. DNS: направить домен на сервер

В панели регистратора домена добавь **A-запись**: имя `shrek` (или `@` для корня), значение — IP сервера.
Проверка с компьютера (через 5–30 минут после изменения):

```bash
nslookup shrek.example.ru
```

Должен вернуться IP сервера. **Не запускай Caddy, пока это не так**: Let's Encrypt не выдаст сертификат и на время заблокирует попытки.

## 2. Подготовить сервер

Зайти:

```bash
ssh root@IP_СЕРВЕРА
```

Обновить систему и поставить Docker (официальный скрипт ставит и Docker Compose):

```bash
apt update && apt upgrade -y
```
```bash
curl -fsSL https://get.docker.com | sh
```

Проверка — обе команды печатают версии:

```bash
docker --version && docker compose version
```

Файрвол: оставить открытыми только SSH и веб.

```bash
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
```

У некоторых хостеров есть ещё свой файрвол в панели — там тоже открой 80 и 443.

## 3. Залить код

Удалённого репозитория у проекта нет, поэтому код отправляется архивом. **В архив попадает только закоммиченное**, так что сначала закоммить всё нужное.

На своём компьютере, в папке `ShrekParty` (Git Bash):

```bash
git archive --format=tar.gz -o shrek.tar.gz HEAD
```
```bash
scp shrek.tar.gz root@IP_СЕРВЕРА:/root/
```

На сервере:

```bash
mkdir -p /opt/shrek && tar -xzf /root/shrek.tar.gz -C /opt/shrek && rm /root/shrek.tar.gz
```

(Если потом заведёшь приватный репозиторий на GitHub, то вместо архива — `git clone` в `/opt/shrek` и `git pull` при обновлении.)

## 4. Настройки

```bash
cd /opt/shrek/deploy && cp .env.example .env && nano .env
```

Что заполнить:

| Ключ | Что это |
|---|---|
| `DOMAIN` | домен из шага 1, без `https://` |
| `Accounts__Admin__Login` / `Password` | вход ведущего в `/admin` |
| `Accounts__Viewer__Login` / `Password` | вход телевизора, он сразу попадает на `/tv` |
| `Party__BirthDate` / `Party__PartyDate` | только если даты не те, что в `appsettings.json` |

Пароли — длинные и случайные: сайт открыт в интернете. Пароль из `.env` применяется при каждом старте, так что сменить его = поправить `.env` и перезапустить.
Сохранить в nano: Ctrl+O, Enter, Ctrl+X.

Файл `.env` содержит пароли — никуда его не копируй и не коммить.

## 5. Запуск

```bash
cd /opt/shrek/deploy && docker compose up -d --build
```

Первая сборка — 3–6 минут: качаются образы .NET и Node, собирается фронт.

Проверка:

```bash
docker compose ps
```

Оба сервиса — `running`. Логи приложения:

```bash
docker compose logs -f app
```

Ждём строку `Now listening on: http://[::]:8080`. Выход из логов — Ctrl+C, контейнер продолжит работать.

Логи Caddy (получил ли сертификат):

```bash
docker compose logs caddy | grep -i -E "certificate|error"
```

## 6. Проверить, что всё работает

1. `https://ДОМЕН` с телефона — открывается регистрация (пока ведущий её не открыл кнопкой «Открыть регистрацию» — экран ожидания), замок в адресной строке.
2. `https://ДОМЕН/login` → учётка ведущего → админка открылась.
3. На телевизоре: `https://ДОМЕН/login` → учётка ТВ → экран ожидания. Нажать «Включить звук и полный экран».
4. Зарегистрироваться с телефона, загрузить аватарку — проверка, что пишутся файлы.

### Репетиция с ботами

С **своего компьютера** (нужен .NET 10 SDK) можно нагнать 10 ботов на боевой сервер и прогнать любую игру:

```bash
dotnet run --project tools/ShrekParty.Rehearsal -- --url https://ДОМЕН --bots 10
```

Боты регистрируются как обычные гости. **После репетиции** — админка → «Сбросить всё» (ввести `СБРОС`). Это удалит игроков, их фото и результаты. Персонал, программа вечера, вопросы, мемы и лоты останутся.

## Обновить код

Снова шаг 3 (архив → сервер, распаковать поверх), потом:

```bash
cd /opt/shrek/deploy && docker compose up -d --build
```

Распаковка поверх не трогает `.env` (его нет в архиве) и данные (они в томе).
Удалённые из проекта файлы на сервере останутся — для чистоты перед распаковкой можно сохранить `.env` и очистить папку:

```bash
cp /opt/shrek/deploy/.env /root/shrek.env && rm -rf /opt/shrek && mkdir -p /opt/shrek && tar -xzf /root/shrek.tar.gz -C /opt/shrek && cp /root/shrek.env /opt/shrek/deploy/.env
```

### ⚠️ Изменения в базе

Миграций нет: схема базы создаётся один раз при первом старте. Если в обновлении поменялись таблицы (новые поля, сущности), старая база с новым кодом **упадёт с ошибкой SQLite** в логах.
Тогда базу придётся создать заново (данные пропадут, поэтому сначала копия — см. ниже):

```bash
cd /opt/shrek/deploy && docker compose down
```
```bash
docker run --rm -v deploy_shrek-data:/data alpine sh -c "mkdir -p /data/old && mv /data/shrek.db* /data/old/"
```
```bash
docker compose up -d
```

Отсюда правило: **финальную версию залить заранее**, за день до праздника. Прогнать репетицию, сделать «Сбросить всё» и после этого код с изменениями базы уже не обновлять. Правки только во фронте и логике без новых полей — можно в любой момент, даже во время праздника: пересборка займёт минуту-две, телефоны переподключатся сами.

## Копия данных

Снять (база + фото + ключи) в папку на сервере:

```bash
cd /opt/shrek/deploy && docker compose cp app:/data /root/backup-$(date +%F-%H%M)
```

Скачать к себе (на своём компьютере):

```bash
scp -r root@IP_СЕРВЕРА:/root/backup-2026-11-06-2300 .
```

Восстановить из копии:

```bash
cd /opt/shrek/deploy && docker compose stop app && docker compose cp /root/backup-2026-11-06-2300/. app:/data && docker compose start app
```

Хорошие моменты для копии: после репетиции и «Сбросить всё», в середине вечера, сразу после финала.

## Частые проблемы

| Что видно | Причина и что делать |
|---|---|
| Браузер ругается на сертификат | DNS ещё не смотрит на сервер или порты 80/443 закрыты. Проверить `nslookup`, файрвол хостера, `docker compose logs caddy`. После исправления — `docker compose restart caddy`. |
| `502 Bad Gateway` | Приложение упало. `docker compose logs app --tail 50`. Частые причины: не заполнены учётки в `.env` («Не задана учётка Admin…»), база от старой версии (см. «Изменения в базе»). |
| Телефоны не обновляются вживую, а после перезагрузки страницы всё верно | Что-то между гостем и сервером режет WebSocket (корпоративный прокси, VPN). Caddy проксирует WebSocket сам; проверить с мобильного интернета. |
| Не загружается видео в Свою игру | Лимит 100 МБ на файл — сжать видео. |
| После обновления у кого-то старая версия | Обновить страницу: `index.html` не кешируется, со второго захода будет новая. |
| Кончилось место | `docker system prune -f` удалит старые слои сборок, данные не тронет. Посмотреть место: `df -h`. |

## Полезные команды

```bash
cd /opt/shrek/deploy
docker compose ps                 # что запущено
docker compose logs -f app        # логи приложения
docker compose restart app        # перезапуск без пересборки
docker compose down               # остановить всё (данные сохранятся)
docker compose up -d              # запустить снова
```

## После праздника

1. Снять копию данных и скачать её к себе: там все фото вечера.
2. `docker compose down`.
3. Удалить сервер в панели хостера (или оставить, если сайт ещё нужен).
